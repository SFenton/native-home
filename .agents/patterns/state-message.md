# State message

> **What:** the empty and error state ("No Chores Due", "Unable to Load Recipes"). **Read when:** a page, tab or sheet can have nothing to show, or its load can fail.

- Mockups: [state-message.html](../design/mockups/proposals/state-message/state-message.html) (before and after, self-contained).
- Canonical component: `HassDesign/StateMessage.swift`. Web: `EmptyState` (`ha-sfenton-react-dash`). HIG: Loading, Layout.
- `StateMessage(symbol:title:message:actionTitle:actionIdentifier:action:identifier:)`: a large secondary glyph (hidden from VoiceOver), a `title2` bold heading, secondary text, and for an error one `PrimaryButton`. It wraps and scales at every text size; the identifier sits on a container so the button keeps its own.
- **Centred in the free space, never a row at the top.** The free space runs from the bottom of whatever the page draws above (the navigation bar, a header such as the Chores quick links, a sheet's title) to the top of whatever sits below it (the floating Add Task bar, the Summary sheet's tab bar, else the tab bar). A page with no header is centred between the nav bar and the bar; one with tiles is centred between the tiles and Add Task. Two placements, no others:
  - `.stateMessage(isPresented:, below:, StateMessage(...))` on a `List` or scroll view whose own content stays: an overlay. The floating bar is a bottom safe-area inset, so the overlay already ends above it. `below` is the global y of a header's bottom edge, written by `.reportsBottomEdge(isActive:into:)` on the header (inactive it reports a constant 0, so a scrolling page writes no state per frame). A state without an action lets touches through to the header; one with an action takes them. Taller than the space at large text, it scrolls.
  - `CenteredStateMessage(StateMessage(...))` where the state *is* the page (Recipes, Inventory); it fills the page and scrolls when taller. Add `.refreshable` outside it when the page pulls to refresh.
- **A failed load always has a way forward (owner, 2026-10-24).** An error state carries `AlertCopy.tryAgain` as its action. `LoadFailure.of(subject, reason:, isOffline:)` (`HassUI/Common/LoadFailure.swift`) words it: online it is "Unable to Load <Subject>" with the loader's reason; offline ( `HassConnection.isOffline`) it is "You're Offline" and "Connect to the internet to load this <subject>." While the retry runs the state stays up and the button shows an inline arc and "Trying Again" (`StateMessage(actionBusyTitle:)`, the busy `PrimaryButton`), so it answers where it was pressed. First user: the Choreapp task sheet (`task.retry`); Recipes and Inventory already used the same shape.
- **Exception: a newer house layout carries no action (2026-11-06).** The `newerSchema` house-layout message ("Update S+H") has no Try Again, because retrying cannot help: the way forward is an app update. Every other failed load keeps the rule above.
- **House-layout states (2026-11-06).** `UKHouseLayoutGate` puts a `UKStateMessageView` through `UKStateMessageOverlay` on every layout-driven page when there is no house document (`houseConfig.state`, action `houseConfig.action`; copy in `HouseConfigCopy`). On a window with a hinge band the overlay sits in the leading region (`UKStateMessageOverlay(leadingOnHinge: true)`); other consumers keep today's centring until a separate change adopts it. The compiled house values are gone (step 7b-2; the `compiledFallbackAvailable` flag is deleted), so a page with no document shows the skeleton, then the message. Its actions open the Home Assistant modal on a page (`HomeAssistantSettingsView.WebPage`), or Try Again with the busy title. See [house-config-states](../design/house-config-states.md) rules 10 to 16.
- Do not use `ContentUnavailableView` for a page's state: it caps its text size and clipped at AX sizes (folded Duo outer panel, 2026-10-12), and as a list row it sat at the top of the page (Chores, Summary tabs, 2026-10-24). Do not hand-build a glyph/title/text stack either.
- Consumers: the Room pages' empty and fallback sheets, the recipe detail's missing sections, the Suggested Recipes error, the Home Assistant web page's error, the placeholder screens, the Choreapp task error, Inventory's signed-out state, the Chores pages (`TodoPageView`), the Summary sheet's chore tabs and Expired Food tab, Recipes (empty and error), Inventory (empty and error). Identifiers kept: `todo.empty`, `summary.empty.<tab>`, `recipes.empty`, `recipes.error`, `recipes.retry`, `inventory.empty`.
- Not covered: inline "none yet" lines inside a form or section (alarms lists), which are plain secondary text in their section; and a recipe's per-section "No Ingredients Available", which sits in the scroll content under the recipe header.
- Tests: `StateMessageTests` (render at default and AX5, the overlay over a list, touch rule) and the Chores, Summary, Food and Inventory journeys.

- **Identifiers.** An identifier on an outer view replaces the one on the state's container. Apply the page's or list's own identifier *before* `.stateMessage(...)` (as `TodoPageView` and the Summary tabs do), or the state loses `todo.empty` / `summary.empty.<tab>`.
- **Too little room.** When the space is smaller than the message (the folded Duo under the Chores quick links, or AX sizes) the message starts at the top of the space and scrolls; content can scroll up under the floating bar's edge. `testEmptyStateIsCentredInTheFreeSpace` asserts centring only when the message fits.
