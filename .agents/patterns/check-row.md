# Check row

> **What:** the one checkable row: a check circle, the text, an optional trailing accessory. **Read when:** a list row toggles a yes/no that is not a setting (a chore, a checklist step, a room in a rule), or you are about to draw a circle or checkmark next to a title.

- **Decided 2026-10-30 (owner: "should both inherit from one base component, or should the chores rows align with the check rows with the edit button elsewhere? Decide with the designer skills").** There is one component, `CheckRow` (`HassDesign/CheckRow.swift`, UIKit `UKCheckRow`, `UIKitPort/Design/UKCheckRow.swift`), with an optional trailing accessory. The chores rows no longer carry their own layout, and the climate room rows no longer carry a trailing checkmark of their own. The edit button stays on the chores row, as its accessory; the other consumers pass none.
- **Why one base, with the circle leading (HIG Lists and tables, Toggles; `design-skills:design-critique`):** a row that checks something off reads as a Reminders-style list, and in that grammar the circle leads and trailing space belongs to a row's own controls (details, edit). The climate pages drew the state as a trailing circle, where a person looks for a disclosure or an edit control, so two rows that do the same thing looked like two different controls. Moving the climate circle to the front, rather than moving the chores edit button elsewhere, keeps the edit button where the swipe-to-edit and the context menu already lead people to look, and it frees no space the rooms need. A switch stays the answer for a setting that takes effect at once (`ModuleToggleRow`, `Toggle`); the check row is for a choice among items or a task being done.
- **Layout (UIKit; the SwiftUI app is gone):**
  - The row carries its own 16 pt leading margin. The check column is 24 pt (`@ScaledMetric(relativeTo: .body)`; `UIFontMetrics(.body)`), the gap 14 pt, so the text starts 16 + 24 + 14 pt in, where `ModuleList` hairlines inset. A `Form` row sets `.listRowInsets(EdgeInsets())` (UIKit: `UKFormRowSpec(fullBleed: true)`) and gets the same edge.
  - The glyph takes the title's font at its default scale and centres on the whole text block (owner, 2026-10-28). 52 pt tall at least, 60 pt with a second line (a due label). 11 pt above and below the text.
  - Everything left of the accessory is the toggle (one VoiceOver element: label, optional value and hint, `isToggle`, or `isSelected` for a selection). The accessory is outside it: its own element and its own 44 pt target. The trailing margin after the row is 16 pt, 4 pt after an icon accessory (the edit button's target carries its own padding) and 12 pt after a text accessory (Undo).
  - Only the glyph dims when the row cannot change; the title keeps its contrast.
- **Tint is the consumer's meaning, not the layout's:** a completed chore and a done checklist step are success green; a room chosen for a rule is the action colour. The component takes `checkedTint` / `uncheckedTint`.
- **Consumers (swept 2026-10-30):** `TodoItemRow` / `UKTodoItemRow` (accessory: edit or Undo), `VacationChecklistRow` / `UKVacationChecklistRow`, `TrackingRoomsDetail` / `UKTrackingRoomsDetail` (the Selected Rooms, Critical Protection and Occupied Only pages). Recipe ingredient rows show a state glyph, not a toggle, and the App Icon picker is a single selection with its own grid, so neither uses it.
- **Tests:** `Tests/HassDesignTests` pin `CheckRowMetrics`; the chores, vacation and climate journeys find the rows by their unchanged identifiers (`todo.item.*`, `todo.edit.*`, `vacation.checklist.*`, `climate.track.*`).
