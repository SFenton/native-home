# Vacuum sheet

> **What:** the robot vacuum sheet (map, status tiles, Controls/Rooms/Auto-Clean/Dock/Info tabs, area editor, cleaning report). **Read when:** opening a vacuum from any screen or changing vacuum controls.

**Redesign decided 2026-10-28** (owner, option B with amendments): [design/vacuum-sheet-redesign.md](../design/vacuum-sheet-redesign.md). ## Using it

```swift
.sheet(item: $vacuum) { vacuum in
    VacuumSheet(vacuum: vacuum, connection: connection)
        .hassSheet(.page)
}
```

## Behavior

- **Runtime mode** (`VacuumRuntime`): full when docked or idle and ready; minimal while cleaning, paused, returning or resumable. Rooms, auto-clean rooms and settings lock outside full mode; the Dock tab shows only the active dock cycle in minimal mode.
- **Settings and rooms are intents.** Each change shows at once, sends `select_option` or `turn_on/off`, and reverts after 8 s unless Home Assistant confirms. Turning a room on picks `vacuum` or `vacuum_and_mop` from the selected rooms' `mop_required` hints.
- **Clean waits for settled settings.** With an unconfirmed intent the clean is queued; it starts once every intent confirms and the store has been quiet for 0.65 s. It fails with a message if settings never confirm (8 s), the vacuum stops being ready, Home Assistant rejects the script, or the robot does not start cleaning within 30 s.
- **Rooms or Area.** Area cleaning (Main Floor) and room selection exclude each other; choosing the other asks first and clears the first (alerts "Use Area?" and "Use Rooms?", `AlertCopy`, system `.alert` on every path: the tile, a room card and a map tap). Areas are drawn in the area editor and sent in centimetres (`x_min_cm`…).
- **Smooth tab and mode changes.** The tab column draws a displayed key (tab + runtime mode) through `SmoothContentSwap`: a tab change fades the old tab out (0.13 s), swaps it while hidden and fades the new one in (0.17 s), like the web's `useSmoothDisplayedModalTab`. Starting or ending a clean (full ⇄ minimal) does the same with a layout animation between, so the setup collapses and the tab control drops or regains Rooms while the content is hidden (web `useVacuumRuntimeContentTransition`). The outgoing mode keeps drawing as it fades: `VacuumControlsTab(mode:)` reads `powerSettings(in:)` / `showsCleaningSetup(in:)`, and the new mode's runtime actions wait for the swap. Reduce Motion swaps at once.
- **Tab state lives outside the sheet's body** (`VacuumSheetContent`), so a tab change redraws only the tab column and never the map canvas. A tab change scrolls the column back to the tab control only when the control is under the bar or above it.
- **Status tiles.** Under the map, Status, Battery and Dock are three equal read-only flat tiles in one row (the read-only face of the tile pattern: caption over value, toned glyph, no sheen, press or chevron); values never size a tile; one column at accessibility sizes. Locate stays the floating glass circle on the map. Notices (unavailable, current issue) follow the tiles.
- **Settings are pop-up rows only** (`VacuumSettingRow`, section "Cleaning Settings"): Mode, Fan, Water and Passes, title left, value and `chevron.up.chevron.down` trailing in `Ink.action`, an inline `Picker` in a `Menu` with the value as the only menu source (a whole-row `Menu` label made the row vanish while open). No segmented controls in the sheet, whatever the option count; at accessibility sizes the value sits under the title. A footer under the group replaces the long per-setting descriptions, which remain the VoiceOver hints. Mode values read "Vacuum", "Mop", "Vacuum and Mop" everywhere, including the row's value: when `input_text.*_vacuum_mode` names a known mode ("Vacuum & Mop") the row shows `VacuumCleaningMode.label`, and any other helper text is shown raw. Recorded departure from the web, which shows the helper text as is (owner, 2026-10-29).
- **Conditional Water and Fan rows.** Water is absent when Mode is Vacuum, Fan when Mode is Mop. The row animates out and in: height with `MotionTokens.standard` (0.3 s smooth, no bounce), content with `MotionTokens.quick` (0.2 s); the group's background, hairlines and 26 pt corners belong to the container so they stay correct at every frame, and the footer and the Clean button are plain layout that slides with it. Reduce Motion cross-fades the row in place at 0.2 s and changes the height at once. The target group (rooms ⇄ area) resizes the column with `standard` under the same rules. Guard rails ([motion](../design/motion.md) section 6 exception), decided by `VacuumShapeMotion` when the change arrives: never on a reconnect or a cold launch from the snapshot (`EntityStore.reapplyGeneration` and the 2 s `TileActionSetTransition.reapplyWindow`, tracked by `VacuumReapplyWatch` as `GlassTile` does), and **applied at once while the sheet scrolls** (the tab column sets `pageIsScrolling` with `pausesTickersWhileScrolling()`, iOS 18 and later). A person cannot pick a Mode mid-scroll, so only a change made elsewhere lands mid-scroll, and holding it back would need the old rows kept on screen for nothing. Signposts: `LayoutChange` pages `Vacuum.settingRows` and `Vacuum.target`; perf tests `testVacuumSettingRowCost` and its Reduce Motion twin ([performance](../testing/apple/performance.md), Layout changes); pure rules and the reveal: `VacuumShapeMotionTests`.
- **Rung 0 for the row reveal** ([change-loop](../workflow/change-loop.md)). The system API is `if` plus `.transition` inside the group's `VStack`. On iOS 17, 18 and 26 it animates the row's insertion, but the container takes its new height at the start of the transaction: the rounded card and its hairlines jump while the row fades, and an asymmetric `.move` slides the row over its neighbours instead of opening space. The card has to follow the row frame by frame, so the row's height is animatable: `VacuumRevealLayout` (a one-child `Layout` whose `animatableData` scales the content's height) is driven by `withAnimation`, and the content leaves the tree in the collapse's `completion`, not after a timer. Precedent: the tile action set's height animation (`TileActionSetTransition`, `GlassTile`), the same token pair and guard rails.
- **Cleaning Target.** Rooms mode: a "Selected Rooms" summary (order chips, or "Full Clean" with the every-area warning when none) and a **Use Area** action tile; no chevron on the summary (it switches to the Rooms section instead of pushing). Area mode: **Edit Area** (subtitle: the area's size), **Clear Area** and **Use Rooms** action tiles, a footer below. A robot without room selection shows only Use Area and Edit/Clear Area. One blue Clean `PrimaryButton`, labelled "Clean" in both modes.
- **Rooms and Auto-Clean are selection tiles** ([action-navigation-tiles](../design/action-navigation-tiles.md), selection-tiles option C and A), two columns, a footer under the grid, long names wrap to two lines (the tile never widens or scrolls). Rooms: chosen is the filled face with the numbered order disc, unchosen is dark with an empty circle disc. Auto-Clean: a check disc, checked is **included**, unchecked reads "Skipped" and is hatched on the map; an unavailable room dims and says Unavailable. Colour cross-fades with `state`.
- **Commands are action tiles.** Pause, Stop, Resume, Dock and Cancel (the run section), Edit Area, Clear Area, Use Area, Use Rooms and every dock command (Clean Mop Dock, Dry Mops, Empty Bin, Stop Dock Clean, Stop Mop Drying) are action tiles (text then disc, `AT` option B). Pause and Stop carry no description; an explanation, when needed, is a footer **below** the tile (dock commands; a disabled command's reason). A running dock wash is the tracked disc (arc spinner) and the filled Stop Dock Clean tile; the Dock status tile reads "Washing". While the robot is still on the dock for its wash during a run (and while it washes or dries) the Dock section stays in minimal mode: only the active command shows (Stop Dock Clean or Stop Mop Drying), never dimmed Dry Mops / Empty Bin tiles beside it (owner, 2026-10-29).
- **Direction G look** (mockups n6-vacuum-*): the subtitle is `.sheetSubtitle("Docked · 100%")`; sections sit in the bottom `.modalTabBar` (five sections, symbols only: Controls, Rooms, Auto-Clean, Dock, Info); lists are `ModuleList`s of `ModuleRow`s (`#2C2C2E` cells at 26 pt in the sheet); the run section has no header card, and while cleaning the map grows to 460 pt and the controls collapse to the run tiles (a run in progress keeps three sections: Controls, Auto-Clean, Info).
- **Room and auto-clean tiles** are at least 76 pt tall; every tile in a grid row matches the tallest (larger than the web's 58 px, owner 2026-10-13).
- **Two columns** only where splits are allowed and the sheet is wide (`MediaRemoteLayout.usesTwoColumns`): map and status on the left, tabs on the right.
- **Accessibility:** room tiles are toggles with their order in the label and Auto-Clean tiles toggles read Included / Skipped; the status tiles are one read-only element each; pop-up rows are buttons with the value; the map is decorative and draws no names (rooms are named on the Rooms tab and in the Selected Rooms summary); the area editor offers Draw (a default area under VoiceOver) and move, grow and shrink actions; every control is at least 44 pt.
