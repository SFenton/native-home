# Settings section

> **What:** a settings page's header + description + controls block, and the pieces that go in it. **Read when:** building a settings-style page (Admin, Guests, Vacation, Sprinklers…).

- `SettingsSection(title:paragraphs:content:)` (`HassDesign/SettingsSection.swift`, web `SettingsSection.tsx`): `HassTokens.Typography.sectionTitle` (`.title3.bold()`, the one section-header font) header with the heading trait, each description paragraph as its own `.subheadline` text in `HassTokens.Ink.secondary`, then the content. Pages stack sections in a `ScrollView` with `Spacing.xl` between them.
- `InlineAlert(_:)`: a warning under the control it concerns (orange triangle, tinted rounded background, primary text); VoiceOver reads "Warning: …".
- `SelectableOptionRow`: one choice in a single-choice set (icon, label, description, checkmark; `.isSelected`; description as the hint). Lay several out with `DynamicGridLayout(minCellWidth: 300, maxColumns: 2)`. Web `ScheduleListRow`.
- Read-only entity values use the read-only entity tile ([entity-tile](entity-tile.md)).

## Section headers, disclosure chevrons and disabled reasons (owner, 2026-10-24)

- **One section-header font.** `HassTokens.Typography.sectionTitle` is `.title3.bold()`; `PageSectionHeader`, `SettingsSection` and `FilterSection` all use it, and the car block is a `SettingsSection`. A bare `FormHeader` inside a `Form` keeps the system header size and case (`proposals/titles-and-headers`). Tile titles are `HassTokens.Typography.tileTitle` (`.subheadline.bold()`).
- **A chevron means push, and nothing else.** `SettingsLinkRow.showsChevron` defaults to false. Set it only for a row that pushes without a `NavigationLink` (the household topics, which push on a phone and fill the detail pane beside the list). Rows that present a sheet or a cover (Home Assistant, Feedback, App Icon) draw no accessory and carry an accessibility hint ("Opens ..."). A `NavigationLink` draws its own chevron. **Owner exception (2026-10-27):** the Settings → Notifications rows (Notifications and Time Sensitive Notifications, `NotificationsSettingsSection`) draw a chevron although they leave the app for iOS Settings, because the owner wants the row to read as a way in; they say "Opens Settings" in their accessibility hint. Do not extend this to other rows that leave the app. A light tile that opens a sheet draws a power button, not a chevron (`BrightnessTile`). The same holds for the Climate advanced-controls rows, the Sprinklers controller row, the vacuum cleaning-report row and the weather card numeral: they open sheets and draw no accessory (a row that must stay a Button because a NavigationLink failed to present on the folded Duo keeps the Button and only loses the accessory). A pop-up `Menu` wears the up-down chevron; Custom Lights' Lighting Mode is one.
- **Say why a control is disabled.** Disable instead of hiding, and put the reason in text beside it: the Sprinkler schedule's Days footer ("Choose at least one day.", `SprinklerSchedulePage.applyBlocker`); the Vacation confirmation sheet keeps Confirm present but disabled with the date error above it (`AwayActionButton(isEnabled:disabledReason:)`).

- **Canonical (UIKit).** `UKSectionBlock.settings(title:paragraphs:content:)` in `UIKitPort/Features/Household/UKHouseholdParts.swift`. `UIKitPort/Design/UKSettingsSection.swift` holds its pieces (`UKInlineAlertView`, `UKSelectableOptionRow`, `UKFormText`, `UKInfoBoxView`).
- **Owned files** (also in `contracts/patterns.json`): `UIKitPort/Design/UKSettingsSection.swift`, `FormSectionText.swift`, `PageSectionHeader.swift`, and the inset-grouped stack: `InsetGroupedStack.swift`, `InsetGroupedSectionView.swift`, `InsetGroupedRow.swift`, `InsetGroupedRowKind.swift`, `InsetGroupedMetrics.swift`, `GroupedRowButtonStyle.swift`.

## Inset grouped pages are a `ScrollView` over a plain `VStack`, not a `List` (owner, 2026-10-27)

- **What.** The Settings tab's root page (`SettingsScreen`, `settings.list`) draws its `Section`s through `InsetGroupedStack` (`HassDesign/InsetGroupedStack.swift`): a `ScrollView` over a non-lazy `VStack`. It reads the sections with `Group(sections:)` (iOS 18), so callers write `Section { rows } header: { } footer: { }` exactly as for a `List`, also inside child views (`AppearanceSettingsSection`, `FeedbackSettingsSection`, ...). Each section becomes a card of rows on the module tint (a sheet's cell colour in a sheet), 0.5 pt hairlines between rows, the header above and the footer below. Before iOS 18 (the deployment target is 17) the page keeps its `List`.
- **Why (departure from `List`, HIG Lists and tables / Layout).** A `List` re-creates and self-sizes every row cell as it enters the viewport (3 to 4 ms per row on the simulator, not cached between passes): 14 ms run-loop turns while Settings scrolled. The page is finite (about 30 rows) and has no swipe actions, editing or selection, so a plain stack builds every row once when the page opens and does nothing per row while scrolling. Do not use it for a long or unbounded list.
- **Row kinds** (`.groupedRow(_:)`): `.link` (default; glyph and text, 15 pt above and below, hairline from the title, press highlight), `.textButton` (a text-only button such as Reset to Default: 15 pt, hairline from the margin), `.control` (a toggle, a slider, a status line: 10.5 pt, hairline from the margin, no highlight). The hairline between two rows takes its inset from the upper row, like the system's.
- **Press highlight.** A button row opts in with `.groupedRowButton()` (`.buttonStyle(.groupedRow)` plus a flag that the button owns the row's padding, so the whole cell is its target; `GroupedRowButtonStyle` reports its pressed state up to the row, which lights the whole cell). A `LongPressGesture` or zero-distance `DragGesture` on the rows was tried and rejected: either stops the scroll view taking drags. Every button and link row in Settings uses it (the topic rows, Home Assistant, the Feedback rows, App Icon, Reset to Default, the notification buttons, About's Version); a button left on `.plain` would draw no highlight and tap only its label. Put a text row's 44 pt minimum height inside the button's label, not outside it.
- **Chevrons.** A `NavigationLink` outside a `List` draws none, so the stack's rows draw `SettingsLinkRow(showsChevron: true)`; `SettingsLinkRow`'s chevron colour is explicit because the accent tint otherwise reaches it.
- **Measured metrics** (matched to the old `List` on iPhone and iPad by screenshot comparison, 2026-10-27): 16 pt side margin (20 pt in a regular-width window: the `List` measured 20 pt on the iPad and the Duo, `InsetGroupedMetrics.regularMargin`), 15 pt leading and 17.5 pt trailing row inset, 28.5 pt above a section (+7 pt above a headerless section that does not follow a footer, a footer gives back 12.5 pt), 10 pt header to card, 8 pt card to footer.
- **The `List` path was removed after the phone A/B (2026-10-28).** Settings is the stack on iOS 18 and later; before iOS 18 (which cannot read a view builder's sections) `SettingsScreen.page` still falls back to a `List`.
