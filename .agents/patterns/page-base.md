# Page base (UIKit port)

> **What:** the one way a page, a pane or a tab hosts its scrolling body, spaces it, pins a bar under it and gets its ground. **Read when:** adding or changing a page, a pane or tab inside a page, sheet or split, a split's empty state, or any bottom bar. UIKit port only (`apple/Sources/HassUI/UIKitPort/App/Page/UKPageBody.swift`, `UKPageViewController`).

Owner decision, 2026-11-01: the page base already owned the header, the wallpaper and the fold; each page still built its own scrolling body and spacing, which is how Chores got 35 pt of dead space and a Food pane a black ground. This makes that impossible.

## The rules

- **Spacing is `UKPageMetrics`** (HassTokens only): side `l` (16), top `m` (12) under the header, bottom `m` (12), between sections `xl` (24), section header to content `s + 2` (10), pinned bar padding `xs` (4) over `l` sides. The SwiftUI pages repeat `padding(.horizontal, .l)`, `padding(.vertical, .m)` and `VStack(spacing: .xl)`; a page never retypes a number.
- **The body is a `UKPageScrollView`** (a measurable column up to `maxWidth`, centred, inside `UKPageMetrics.padding`) installed with `install(scrollView:)`, or any scroll or collection view named with `setPageScrollView(_:)`. `UKColumnScrollView` is the same view with zero padding for a body whose sections inset themselves (Home, Security). The base sets `contentInsetAdjustmentBehavior = .automatic` (the bar, the large title and a pinned bar arrive as the safe area), transparent, scroll-only-when-needed ([scroll-fit](scroll-fit.md)), the soft top edge and the header fade. A page never sets `contentInset`, `contentInsetAdjustmentBehavior` or its own top constant. The one exception is the centred state message, which lays out in the whole frame.
- **A page body never scrolls sideways.** `UKScrollFit.pinWidth` switches off horizontal bounce and indicator and puts back any horizontal offset; the page still pins its content width to the frame (`contentLayoutGuide` width = `frameLayoutGuide` width, or a frame-set content size).
- **A bar under the page is `UKPagePinnedBar`.** Its height joins the page's `additionalSafeAreaInsets` once, there; no page computes a bottom inset. A page's debug or status strip is `UKPageViewController.bottomAccessory` (installed by the base on the bar material through `UKPagePinnedBar.accessory`). The keyboard inset of a sheet's columns (`UKMediaRemoteSheet`) and the floating action bar's per-column list inset (`UKTodoPageViewController`, `UKFloatingActionBar`) are separate mechanisms and stay.
- **The page base owns the ground.** On the wallpaper the view is clear over `UKBackdropView`; in a sheet it is the system grouped ground, or a sheet backdrop set with `setSheetBackdrop`. A page does not set `view.backgroundColor`. A page shown as a pane (`UKContext.isPane`, the Settings split's trailing navigation) creates no backdrop at all: the host's wallpaper is the ground, so no second blurred layer sits over it. A debug build logs `PAGEGROUND` for a page that painted one.
- **A pane or tab is a `UKPaneViewController`**: clear, never painting a ground (`PANEGROUND` in debug), spacing from `UKPageMetrics`. The host (the page, the sheet, the split's container) draws the ground. It is a plain view controller with no assumption about its parent, so it works as a column of a split or navigation host as well as a child of a page. Galleries, the shell and root controllers are exempt.
- **One empty state for a split's pane**: `UKPanePlaceholderViewController(symbol:text:identifier:)` (the todo page's look: large symbol, headline in the secondary ink, one combined element). Settings, Food spaces and the todo page use it.

## Column navigation

A page that opens another page beside it does not build its own split: it hosts a `UKColumnsViewController` (root column, shared empty state, `show(_:sender:)` to open, `setDetail` for a single editor or form) and the owner flips `setWide`. Entries are `UKPaneViewController`-style: clear, with the page-base spacing; the columns draw no header and host no navigation controllers: the section's own bar spans both columns (page header, edge fade, the shell group trailing, and a separate leading column group with Back or Close that sits above it in the Duo's rail and never folds into More), and a column page's title is a large heading in its own scroll content (`UKColumnTitleHeader`, attached by the page base while the page is a child of the columns). The host draws the wallpaper. See [split-view](../design/apple/split-view.md), Column navigation.

**The empty state's order (owner, 2026-11-01), done once in the container for every split built on it.** Opening the first page: the empty state fades out (`quick`), and only then does the page animate in. Closing the last page (Close, Back to no pages, `closeAll`, `setDetail(nil)`, the edge pan): the page animates out, and only then does the empty state fade in. Replacing a page or drilling while pages remain never touches it. Reduce Motion cross-fades in the same order. The final state always matches `entries.isEmpty`: each commit bumps a generation counter, so an overtaken fade does nothing and a no-change commit settles the empty state. Nothing animates from `layoutSubviews`; a fold or rotation while empty only relayouts the empty state.

## Left as they are

`UKFloatingActionBar` (Todo), the keyboard inset in `UKMediaRemoteSheet`, the pagers (`UKPaging`, the Food hub pager, the chip rail: horizontal scrollers with `.never`), `UKCenteredStateMessageView` (`.never`), `UKLoginViewController` and the flyout (`.always`, outside the page base), the Vacuum sheet's section bar (already `UKPagePinnedBar`).

## Tests

- **`houseLayoutSkeleton` (2026-11-06, house-config-states rules 10 to 14).** `UKPageViewController.houseLayoutSkeleton` is nil by default: the page never depends on the house document (navigation chrome, Settings root, Profile, the Home Assistant modal, state pages). A page that draws from the house layout overrides it with `.home` (Home) or `.page` (Security, Climate, Rooms and Room pages, Room overview, Media, Custom Lights, Sprinklers, Vacuums, Food hub, Vacation, Chores todo pages, household column pages). The base then makes one `UKHouseLayoutGate` in `viewDidLoad`: with no document it holds `contentView` back (`UKContentReveal.hold`: laid out, invisible, unreachable) and draws a `UKConfigSkeletonView` or a state message over it; with a document it does nothing. Subclasses add content to `contentView` as usual and need no other code.
