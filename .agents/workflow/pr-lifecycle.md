# PR lifecycle

> **What:** how a session ends: from a pushed branch to a merged, blocked or failed one-line report, with the review and the gate that stand between. **Read when:** you are about to open a PR, or you were woken by a CI or review event.

Owner decision (2026-10-28): agents merge once the required checks are green and a review is recorded. The repo goes private on GitHub Free, which enforces neither rulesets nor auto-merge, so [`tools/pr_land.sh`](../../tools/pr_land.sh) is the gate and a hook stops anything else from merging.

## The standard ending

1. **Ship.** `tools/ship.sh "Subject" --pr --draft [--note TEXT]` commits (trailers `Release-Note:` and `Co-Authored-By:`), pushes and opens a **draft** PR (always a draft) with [`.github/pull_request_template.md`](../../.github/pull_request_template.md) as the PR template. `ship.sh` itself does not apply it: right after it opens the PR the orchestrator runs `python3 tools/pr_note.py init --task T` (see PR timeline). `pr_land.sh` marks it ready once its checks and review pass.
1b. **Preflight.** Right after the draft PR opens, and before the first review for any head more than 50 commits ahead of its base, run `python3 tools/land_preflight.py --pr N` (read-only; it never merges, edits or pushes). It checks that the base ref carries the files the gated path runs from the base (`tools/lane_land.py`, `tools/pr_land.py`, `tools/pr_land.sh`, `tools/triage/config.json`, plus `tools/jev_gate.py` when the PR touches app-UI paths), and reports commits ahead, whether a review is recorded for the head and whether checks have reported. Exit 0 means the gated path can land; exit 3 prints `owner-only: <reason>` and the missing files. **Rule:** a long-lived shared base lands any gate-file changes on `main` in an early, separate PR, and its final PR is opened only once the preflight exits 0 (PR 308 found a base without `tools/lane_land.py` only at land time).
2. **Bind and watch.** Claude app sessions bind the PR and turn on auto-fix: `ccd_pr` `get_status` (read the PR and its checks instead of polling `gh pr checks`), `bind_pr` with the URL if the PR bar did not pick it up, `set_monitor` with `auto_fix: true`. CI failures, merge conflicts and review comments then wake the session. Other runners (triage) read `gh pr view` once.
3. **Fix.** Fix failing checks and valid review comments with small commits; push. Never poll ([token-economy](token-economy.md)). After a `changes` verdict, `python3 tools/jev_hints.py findings build/review/<branch>.json` groups the blocker and major findings into one checklist per kind (nothing when the decision model is unavailable; the findings themselves stay authoritative).
4. **Review.** Spawn the reviewer: `Agent(subagent_type: "reviewer", prompt: "opus-ok: final review. PR N, branch B, round R ...")`. It is an Opus subagent defined in [`.claude/agents/reviewer.md`](../../.claude/agents/reviewer.md), starts from the Jev pre-read (`tools/jev_hints.py review --pr N`, [decision-models](decision-models.md); a guess to verify), runs the ten-item checklist below and records its verdict with `tools/review/record.py verdict.json --pr N`. `changes` sends you back to step 3; run it again for round 2. Findings marked `blocker` always stop the merge. With a detached HEAD pass `--pr N` to `record.py`.
5. **Land.** `tools/pr_land.sh N` (add `--dry-run` to see the decision). An agent runs the project's absolute `tools/pr_land.sh N` from the project checkout; `merge_guard` refuses it unless that checkout's `pr_land.sh`, `pr_land.py`, `house_scan.py` and `tools/triage/config.json` match `origin/<base>`, so fetch or rebase when your base is stale.
6. **Report** one line: `merged #N`, `blocked #N: reason` or `failed #N: reason`, exactly what `pr_land.sh` printed. Do not summarise the diff again.

## PR timeline

A change is followed from the PR alone: the description is the living view (what changed for you, one hero pair, the device table, the status line, the reviewer block) and comments are point-in-time events. `python3 tools/pr_note.py` (spec: `build/research/visual-prs.md` J and K.6) is the one writer. `post pick|evidence|verdict|owner|handoff|shipped --task T --round N --body-file F` finds its earlier comment by marker (`<!-- sh:<kind>:<task>:<round> -->`; evidence adds the class, `iphone`, `duo` or `ipad`, one comment per class per round and none for a class with nothing to show) and edits it only when the body changed. `status --line` and `devices --file` replace only the text between `sh-status` and `sh-devices` markers; the `review:` block belongs to `tools/review/record.py`. Before the PR exists notes queue under `build/pr-notes/<task>/` (keyed by the `--task` id the roles pass) with their original time. Right after `ship.sh` opens the PR the orchestrator runs `python3 tools/pr_note.py init --task T`: it makes the body follow the template (prepends the plain sections if missing, appends missing marker blocks, keeps existing text and the review block) and posts the queue; every later `post` flushes the task's queue first and drops stale queued entries. A `gh` error or a 20 second timeout prints one warning and exits 0. Who posts: the Verifier evidence, the Designer pick and verdict, the Orchestrator handoff (work waiting over 30 minutes or changing hands; `resolve` when it ends), owner, shipped and the status line. Budget: L0 none, L1 about 2, L2 design about 6, more only when a change shows on several device classes.

With no key it says so on stderr and posts as the owner's `gh` login, exactly as without `--as`.

Steward and triage may also be installed on the request repo (local setting, [triage setup](triage-agent.md#the-request-repository-local-setting)) (optional). `pr_note` recognises an app by its recorded slug (`s-h-<role>` when none), and `gh_app_token` looks up a missing installation id with the app JWT (`GET /app/installations`, account SFenton). `python3 tools/gh_app_token.py check <role>` prints whether the key is present and the app reachable, never a token. ## The gate: `tools/pr_land.sh N`

Merges (squash, pinned to the head SHA reviewed) only when all hold:

- The PR is open, not conflicting, and checks are green on the head SHA, and the required check `pr-checks` (the aggregate job of [`pr-checks.yml`](../../.github/workflows/pr-checks.yml), run by the self-hosted Mac runner, see [ci](ci.md)) is green. A missing, running or failed check blocks. Only the newest run of each check counts (by `startedAt`, per workflow and job name, or per `detailsUrl` host when there is no workflow; the zero time `0001-…` that `gh` prints counts as no `startedAt`; a queued re-run counts as newest, a completed run without `startedAt` as oldest, and on an equal `startedAt` the less green run wins), so the failures of a superseded run on the same SHA, still listed after a close and reopen or `gh run rerun`, do not block.
- `build/review/<branch>.json` (each `/` in the branch becomes `__`; looked up in the current checkout, the PR branch's worktree and the main checkout) was recorded for **exactly the PR's head SHA** (a review of an older head, or without one, blocks) and has `verdict: pass`, or `verdict: changes` in round 2 or later with no `blocker` finding.
- The app-UI gate passes ([agent-roster](agent-roster.md#autonomy-levels), "What code enforces today"). Two owner decisions of 2026-11-04 shape it: an `Owner's request: "<quote>"` line in an interactive PR counts as the owner's request when the quote is inside a prompt the owner typed in the last 14 days (logged by the `UserPromptSubmit` hook `tools/hooks/owner_prompt_log.py` to `~/hass-agents/owner-prompts/`; a tripwire, not a boundary: agents run as the owner's user, and `tools/hooks/owner_prompt_guard.py` plus the runner's deny list only make forging it a deliberate act); and a mockup file whose drawn form is unchanged after stripping comments outside `<script>`, citation attributes, `<a>` hrefs and metadata (`lane_land.mockup_drawn_form`) is not app UI, so a citation-only rewrite of the atlas skips the gate.
- No kill switch is set: `$HASS_TRIAGE_PAUSED_FILE` (the triage runner exports its `PAUSED` file) or `~/.config/fenton-hass/NO_LAND` exists. Either one makes it print `blocked: landing paused` and exit 1.

`REQUIRED_CHECKS` in `pr_land.py` is `["pr-checks"]`; a PR without that check counts as pending (the aggregate runs on whichever Mac runner is idle, but `scope`, `repo-checks` and `swift-test` run on `hass-mac`, so a PR queues while the MacBook is asleep, off or busy, until hosted runners land; owner, 2026-11-07). `--review FILE` is accepted only with `--dry-run`.

Then it marks a draft ready (only after the gate passed), merges, deletes the remote branch and prints one line. It removes the lane worktree and local branch only when the local tip equals the merged head, the worktree does not contain your working directory and `--keep-worktree` is not given; otherwise it keeps them and prints the command to remove them. It also keeps the worktree when it has uncommitted or untracked files, is locked, a devcap hold or a live process has its cwd inside it, or it holds a hand-off note (the `ci_hygiene.reap_blocker` checks; `lsof` or devcap unreadable keeps it), and the whole cleanup is best effort: an exception there never changes the merge result (owner, 2026-11-04). `lane_land` does the same for an `agents/*` lane after its push: it deletes the remote branch (only while it is still at the merged SHA), removes the clean worktree and the local branch, and logs each decision as `reaper: ...`; `ci_hygiene` does not tag devcap holds or simulators to a lane, so none are released. Triage and any session that still needs its worktree after landing pass `--keep-worktree`. Exit 0 merged, 1 blocked, 2 failed. The logic is in `tools/pr_land.py` and tested in `tools/tests/test_pr_land.py`.

**Merge path for native-home (owner, 2026-11-08).** GitHub is the gate, not a local hook: the ruleset `main-checks` requires the `pr-checks` check and one approving review ([ci](ci.md#the-merge-gate) has the JSON). `pr-checks` also has an author step, but it is advisory (a PR can edit its own workflow); the real author check is the reviewer (no approval for a PR not authored by `SFenton` from this repository) and `merge_guard` (`gh pr view` author and head repository). The reviewer subagent approves (or requests changes) as the S+H Reviewer GitHub App (`tools/gh_app_token.py review`, a reviewer-only token with `pull_requests: write`, pinned to the reviewed head), so GitHub sees an approver who is not the author. `tools/ship.sh` opens the PR and, only while `tools/ruleset_gate.py` finds the ruleset live on `main` (an approval, stale reviews dismissed on push, `pr-checks` from GitHub Actions, no bypass; it fails closed: a failed `gh api` or a missing rule prints a notice and arms nothing), marks it ready and arms `gh pr merge N -R SFenton/native-home --auto --squash`. GitHub then merges when `pr-checks` is green and the reviewer app has approved. A push after approval dismisses the approval (`dismiss_stale_reviews_on_push`), so the PR waits for a new review of the new head; pushing to an armed PR is therefore safe and needs no disarming. `merge_guard` allows exactly `gh pr merge N -R SFenton/native-home --auto --squash` and `--disable-auto` on `SFenton/native-home` (interactive sessions only, the PR based on `main`, authored by `SFenton` from `SFenton/native-home`, the same ruleset check at hook time); `--admin`, `--merge`, `--rebase`, `--match-head-commit`, `--delete-branch`, any other repo and any shell trick stay refused. Tests: `tools/tests/test_merge_guard_automerge.py`, `test_ruleset_gate.py`, `test_lane_ship.py`.

The `merge_guard` PreToolUse hook (`tools/hooks/merge_guard.py`, registered in `.claude/settings.json`) blocks a bare `gh pr merge`, `gh api …/pulls/N/merge` (and `…/merges`) and a `git push` to `main` or `primary` unless the command goes through `tools/pr_land.sh`. The owner can still merge by hand. `.claude/settings.json` allows `tools/pr_land.sh` and `tools/ship.sh` in the relative, `./` and this repo's absolute-path forms so none prompts; `tools/clean.sh` is allowed in the relative and `./` forms. There is no `rm` allow: remove stale build output with `tools/clean.sh PATH...`, never bare `rm -rf`. It deletes only strictly inside `build/`, `apple/.build` and `apple/.build-*`, the same under `.claude/worktrees/<name>/`, and `/tmp/claude-<uid>` (real directory, owned by you); it ignores any root that is or passes through a symlink, unlinks a symlink argument instead of following it, and refuses everything else.

The Python tool tests step of `pr-checks` ignores failures already present on the PR's base commit and fails only on new ones (`tools/ci_new_failures.py`; owner, 2026-11-04). A push or manual run still runs `tools/run_tool_tests.sh` plainly.

## Registry checks (for `pr-checks`)

Three commands run in the `repo-checks` job of [`pr-checks.yml`](../../.github/workflows/pr-checks.yml) on every PR (you can run them yourself first; they are cheap and stdlib-only): `python3 tools/pattern_guard.py` (registry, ownership of every shared file, regex guards; exit 1 on any error), `python3 tools/components_index.py --check` (exit 1 when `contracts/components.json` is stale; fix with `python3 tools/components_index.py` and commit) and `python3 tools/jev_ask.py sync --check` (exit 1 when the `context.patterns` criteria no longer match `contracts/patterns.json`; fix with `sync`, bump the question's `version`). `python3 tools/pattern_guard.py changed --base origin/main --strict` is the advisory form: it exits 1 when a pattern's files changed without its doc or `contracts/patterns.json`.

## Preflight review

`tools/ship.sh` runs `python3 tools/preflight_review.py --base BASE` after it commits and before it pushes, on the diff `origin/BASE...HEAD` (skipped when `origin/BASE` is unknown). It is **advisory**: every check only prints a `warn [check] file:line` line, nothing fails the ship, and a crash or git error in the tool prints one line and the ship continues (like `base_drift`). It exists because the same three findings kept costing a second review round (post-mortem `build/retro/house-config-runtime.md`, action 3). Blocking can be turned on once the false-positive rate on real PRs is zero (replayed on #368 and #367 it reports nothing unreal). `--base` and `--head` take any rev, so `--base 43951d72 --head 14b913e3` replays a merged PR.

1. **`stale-doc-name`.** A Swift declaration the diff removes that the head no longer declares anywhere in `apple/` (whole names, one `git grep` of the head), and a repo path it deletes or renames. Only type declarations and type members of non-test `apple/Sources` files count (the enclosing type comes from the base file; locals, `case` patterns and test files do not). A `.agents/**/*.md` line (not `.agents/archive/`) is reported when it names a full path, `Type.member`, or a camelCase or type name of 6+ characters inside a backtick code span; plain lowercase words and prose never match.
2. **`facade-guard`.** A new or changed non-private `static` member (property or zero-argument function) in `apple/Sources` that calls `HouseConfigSource.active.read` (or the file's own `read { }` helper) whose enclosing type and name are not in the `facades` map of the `static-let-reads-house-facade` guard in `contracts/patterns.json`. The map is loaded through `pattern_guard`, the one `HouseFacadeGuardTests` exercises; `HouseConfigSource` itself and `read:` parameters are skipped.
3. **`fails-if`.** A test added under `apple/Tests` (`func test…`) or `tools/tests` (`def test…`, found with `ast`) with no `Fails if:` line in its doc comment (Swift `///`, Python docstring or `#` lines above) and none naming it on a `Fails if` line of the PR body (`ship.sh --body`). The line says what change to the code under test makes the test go red.

`ship.sh` is not the merge path; `pr_land` and `lane_land` do not call this.

## What the hook does not stop

`merge_guard` allows exactly `tools/pr_land.sh ARGS` (also `./tools/…` or this repo's absolute path, no shell metacharacters) and scans every other command: it splits on `; && || | &`, parentheses, braces, backticks, `$(` and `then`/`do`/`else`, strips `env`/`command`/`exec`/`nohup`/`time`/`xargs`, compares the program by basename, skips `git -C/-c/--git-dir`, and also blocks the GraphQL merge mutations and a PUT or DELETE on `/contents/`. **One exemption (owner, 2026-11-04):** that scan stays the decision, and a block is dropped only when every simple command of the input is a non-executing one: `grep`, `rg`, `cat`, `head`, `tail`, `less`, `ls`, `wc`, `echo`, `mkdir`, `git log|show|diff|status|commit` (no `-c`), `gh pr view|list`, or `python3` of an allow-listed script (`tools/tasks.py`, `pr_note.py`, `affected_tests.py`, `jev_gate.py`, `retro_digest.py`, which never run their arguments; never `bg_run.py`, `devcap.py`, `ship.sh`, `pr_land`, `lane_land` or `tools/triage`), with no `$'`/`$"`, substitution, subshell, `/dev/stdin`, shell, other interpreter, `find`, `sed`, `awk`, `xargs`, `env` or wrapper, and no heredoc but `cat > file <<WORD` (whose body is then data). So a `grep` for `--owner-ack`, or a brief written with `cat > file <<'EOF'` that mentions `lane_land`, passes; anything else, and any parse failure, keeps the raw verdict. `agent_status.py` and `lane_base.py` exist but are not on that list until read. **Protected paths (owner, 2026-11-07):** see "The owner-kept set is enforced on every route" below; `tools/retro_phase.py` and the merge path itself are no longer protected, an independent review is their gate. **Out of scope:** `curl`, interpreters (`python -c`) and script files that call GitHub. The hook stops the model by accident or by habit, not a determined one; the triage deny list and the owner's review cover the rest.

## The verdict

```json
{"verdict": "pass|changes|blocker",
 "findings": [{"severity": "blocker|major|minor", "rule": "system-api-first", "file": "...", "detail": "...", "fix": "..."}]}
```

The verdict must follow from the severities: `pass` means only minors, `changes` a major and no blocker, `blocker` any blocker; `record.py` rejects a mismatch. It adds `head` (the reviewed commit) and `round` (1, bumped only when the head moved after a `changes` verdict; any `round` in the input is ignored), writes `build/review/<branch>.json`, and replaces the `<!-- review:start -->` section of the PR body with a summary. After two rounds a `changes` verdict lands unless a blocker remains; a blocker goes to the owner. `record.py` enforces the round cap: recording round 3 or later is refused unless you pass `--confirm-round "reason"`, and the reason is stored as `round_confirmation`. That is for a confirmation pass that finds no blockers. A `blocker` verdict at round 3 or later is refused even with `--confirm-round`: a blocker after round 2 parks the PR as Needs Decision.

The orchestrator puts the exact lane verdict path, from `python3 tools/review/lane_verdict_path.py LANE` (it prints `lane_land.review_path` for the full head sha and writes nothing), in the spawn prompt of every lane reviewer; reviewers never type it by hand.

A base merge into a PR branch runs in the branch's own worktree, or detached and pushed with `HEAD:<branch>`, never in a new checkout of the branch.

## The reviewer's checklist

The same ten items are in the PR template.

1. `/swiftui-pro` on the diff ([how](swiftui-pro.md)).
2. `apple-hig` for UI diffs, citing the HIG section.
3. Pattern reuse ([patterns](../patterns/README.md)): `python3 tools/pattern_guard.py changed --base origin/main` lists the patterns the diff touches and whether their docs moved with them; `python3 tools/pattern_guard.py` must report 0 errors.
4. System API first ([rung 0](change-loop.md#rung-0-system-api-first)).
5. Unit tests, and a UX test and an accessibility test per affected device family.
6. The surface's mockup updated and the hub republished.
7. For visible changes, the design decision record ([propose-first](propose-first.md): options judged, the pick).
8. `HassCore` / `HassDesign` / `HassUI` layering.
9. The performance invariants in [AGENTS.md](../../AGENTS.md).
10. An invariants sweep: no secrets in the diff, `Release-Note` trailers, native only, no new `#if os(macOS)`, devcap holds in new tooling, docs updated, DocC.

Open workflow fixes (guards, the lander, CI on the base, coverage classification) and the branch divergence are tracked in [workflow-roadmap](workflow-roadmap.md).

## Triage

The [triage runner](triage-agent.md) works the same way: its worker follows steps 1 to 5 in the `report/N` branch and lands with `pr_land.sh`. It lands with `tools/pr_land.sh N --keep-worktree` (the runner cleans its own worktree). `config.json` keeps the `gh pr merge` and `gh api …/merge` denies, which do not affect the `gh` calls `pr_land.sh` makes itself, and allows `Bash(tools/pr_land.sh*)`; the runner exports `HASS_TRIAGE_PAUSED_FILE`, so its `PAUSED` file stops landing too. ## The local workflow base

Never merge, cherry-pick or commit onto a local copy of the workflow base (`main`, the same as the product base). Lanes reach it only through `pr_land.sh` (product) or `lane_land.py` (self-changes). Local-only commits there are invisible to every tool and have twice needed a rescue PR (#302; 36 unpushed merges in `uikit-port-root`). Run `python3 tools/base_drift.py` (after a `git fetch origin main`) before resetting or aligning any local base: it lists the commits `origin/<base>` lacks on the local base, on each `--branch` and on every non-lane branch tracking the base (lanes `agents/*` and `claude/*` track it by default, so name one with `--branch`), and exits 3 if there are any. The default base is `workflow_base` of the triage config. `tools/ship.sh` prints it as a warning and never fails because of it.

## Kill guard

The `kill_guard` PreToolUse hook (`tools/hooks/kill_guard.py`, registered next to `merge_guard` in `.claude/settings.json`, tested in `tools/tests/test_kill_guard.py`) blocks process kills that are not scoped to the agent's own work. Cause: on 2026-10-30 a machine-wide `pkill -f "swift-test|swift-testing|swift-build|xctest"` killed the self-hosted runner's swift-test job (exit 143). This Mac is shared by agent sessions, the Actions runner, devcap holds and simulators. Blocked: `killall`; `pkill -P 1`; `pkill` without `-f`; `pkill -f` unless every `|` alternative starts with an absolute path inside your own worktree (the git toplevel of the hook `cwd`, never the project root or a sibling lane, and not a bare root or a root plus a wildcard) or the scratchpad `/private/tmp/claude-<uid>/` (`$PWD`, `$CLAUDE_PROJECT_DIR` and `~` are expanded first); the same for the `grep` in `ps … | grep … | xargs kill`; shell keywords and `timeout`/`watch` wrappers are looked through; any pattern naming `Runner.Listener`, `Runner.Worker`, `actions-runner`, `devcap`, `Simulator`, `CoreSimulator` or `launchd` (even inside a scoped path); `kill $(pgrep …)`, `` kill `pgrep …` `` and `pgrep … | xargs kill` with an unscoped pgrep; `xcrun simctl shutdown all` `erase all` and `delete all`. Allowed: `kill PID`, `kill %1`, `pkill -P PID`, and a `pgrep` that kills nothing or only literal PIDs. The override is a real comment, `# kill-ok: reason`. Instead: kill the PID you started, scope `pkill -f` to your worktree path, or add the override. The triage deny list also refuses `killall`.

After a `cd`, `pushd` or `popd` anywhere in the command, `$PWD` and `$(pwd)` are not expanded (they no longer name the hook's directory), so a pattern built from them is unscoped and blocks. `grep` and `awk` count as the lookup only inside a pipeline fed by `ps`; `ps … | xargs kill` with no scoped filter blocks. The shell splitting (comments, heredocs, wrappers) lives in `tools/hooks/shell_parse.py`, shared with the worktree guard; a heredoc marker counts only outside quotes, `# kill-ok:` only outside heredoc bodies, and a comment inside backticks ends at the closing backtick. Also looked through: `find -exec`, `env -S` (also in a cluster such as `env -iS`), `xargs`/`parallel`, `pidof`, `pkill -P 1,2` and a heredoc fed to `bash`/`sh`.

**What the kill guard does not stop:** aliases and shell functions, a command held in a variable (`$cmd`) or built for `eval` from variables, script files and interpreters (`python -c "os.kill…"`, `osascript`), `kill` of a PID taken from a variable the agent got from somewhere unscoped, and `$PWD` tricks the hook cannot see (for example `cd` inside a sourced script, or `find -execdir sh -c '…$PWD…'`, where `$PWD` is the directory `find` entered, not yours). It stops a model by accident or habit, not a determined one.

## Worktree guard

The `worktree_guard` hook (`tools/hooks/worktree_guard.py`, registered in `.claude/settings.json` for Bash, for `Edit|Write|MultiEdit|NotebookEdit` and at SessionStart; tested in `tools/tests/test_worktree_guard.py`; the shell splitting is shared with the kill guard in `tools/hooks/shell_parse.py`) keeps sessions out of a repository's shared primary checkout (owner, 2026-10-30: one session, one worktree). A checkout is primary when git's absolute git dir equals its common dir; a linked worktree is always fine wherever it lives (`.claude/worktrees/*`, the triage runner's `~/hass-agents/worktrees/N`). Git decides, never a path or device name.

- **Session start** in a primary checkout adds a note: call `EnterWorktree` with a short kebab-case topic name before any edit, commit or branch change.
- **Edit tools** are denied for a path in a primary checkout unless git ignores it (`git check-ignore --no-index`: `build/handoff`, `.build` and scratch output stay writable). Outside git, in a linked worktree, or in a worktree nested under a primary, they pass.
- **Bash** is denied when the effective directory is in a primary checkout (`cd`, `pushd`, `git -C` and `env -C` are followed; `$PWD`, `$(pwd)`, `$HOME`, `~` and `$CLAUDE_PROJECT_DIR` are expanded) for: `git commit|add|rm|mv|restore|checkout|switch|reset|merge|rebase|pull|cherry-pick|revert|am|clean`, `git apply` (not `--check`/`--stat`), `git stash` (not `list`/`show`); `sed -i`, `perl -i`, `tee`, `>`/`>>` redirects, `touch`, the destination of `cp`/`mv`/`ln`/`install` (and the sources of `mv`), and `rm`/`rmdir` targets, when the target is in a primary checkout and not git-ignored; and `tools/ship.sh` run from there. `/dev/*` and file descriptors are fine. Allowed: `status`, `diff`, `log`, `show`, `fetch`, `branch`, `push` (the merge guard covers `main`), `git worktree add|list|remove|prune`, `git <sub> --help|-h`.
- **Also blocked in a primary checkout:** `gh pr checkout` and `gh repo sync` (they change the branch), `git branch -m|-M|--move`, `truncate`, `patch` (not `--dry-run`), and a mutating git subcommand aimed at the primary checkout from elsewhere with `GIT_DIR=`/`GIT_WORK_TREE=` (bare or after `env`) or `--git-dir`/`--work-tree`. Reading and creating with `gh` (`pr view`, `pr create`, `issue …`) stays fine.
- **Scope:** only the project's own repository: the guard compares the target's git common dir with that of `$CLAUDE_PROJECT_DIR` (the hook `cwd` when unset), so a scratch `git init` under `/tmp` is never blocked, and a project dir that is itself a linked worktree still guards the primary checkout. If neither is in a repository, nothing is guarded.
- **False positives avoided:** a path made by an earlier `git worktree add` in the same command counts as a linked worktree (`git worktree add ../w -b w && cd ../w && git commit`); `[[ a > b ]]`, `(( 1 > 2 ))` and `$((1>2))` are not redirects. A backslash-newline joins lines. A `"$(…)"` or backtick substitution inside double quotes is parsed as its own context (quotes and heredocs inside it start fresh) and its commands are checked. Ignored-path checks run as one `git check-ignore --stdin` per repository.
- **Override:** a real comment, `# worktree-ok: reason`, outside quotes and heredoc bodies. Use it only when the owner asked for work in the primary checkout.
- **Fails open:** bad input or a git failure allows the call.

**What the worktree guard does not stop:** aliases and shell functions, a path or command held in a variable (`cd $DIR`, `$cmd`), `eval` built from variables, scripts and interpreters that write (`python -c`, `make`, `npm`), `xargs` and `find -exec` writers, `dd`, `mkdir`, `curl -o`, `patch -d DIR` or a patch file that names other paths, `GIT_DIR`/`GIT_WORK_TREE` set by a separate `export` or assignment statement, `git branch -d|-D|-f|-c` and `git tag`/`git update-ref` (ref changes that leave the checkout alone), `git worktree` commands run against the primary itself, `awk -i inplace`, `ed` and `python`-style writers, a substitution's `cd` (its commands are checked in the directory the whole command ends in), and `cd` inside a sourced script. It stops a model by accident or habit, not a determined one.

## Review-only merges and the denylist (owner, 2026-11-07)

- **Review is the gate.** `tools/pr_land.sh N` merges after an independent reviewer's `pass` for the exact head (a verdict `tools/review/record.py` wrote for the reviewer, see below), the app-UI gate, the owner-kept set check, mergeability and the local checks. `require_checks` in `tools/triage/config.json` (default true; `false` in this private repo) switches off the `pr-checks` requirement only. A public repo sets it true and runs a hosted `pr-checks` aggregate job. The release note is not checked by `pr_land`: `tools/ship.sh --note` adds the `Release-Note:` trailer, and a squash carries it. `merge_guard` pins `pr_land.py`, `house_scan.py` and the config to the base branch's copy for `pr_land.sh`, and `lane_land.py` (with `release_closure.py`) and the config for an interactive `lane_land`, so a PR cannot change what the gate asks for.
- **Dropped when `require_checks` is false.** The full tool suite and the Swift suites (CI only). Not dropped: `pr_land` runs, on the exact head with the **base's** copies of the tools and of `contracts/house_scan.json`, `house_scan check` (every rule, the debt ratchet) and `pattern_guard`; and the denylist new-hits check. A head or base it cannot read refuses. The PR body of a change that relies on this lists the two suites as not run.
- **The owner-kept set is enforced on every route.** One list (`lane_land.protected_set`: `DEFAULT_PROTECTED`, the config's `protected_paths` and every file the `ios-release*` jobs run or import, derived by `tools/release_closure.py` from the workflow steps) drives both routes: `lane_land` refuses a lane and `pr_land` (through the app-UI gate, run from the base copy) refuses a pull request that adds, edits, deletes or renames any of it, and nothing merges. The set: credentials (`tools/hass_creds.sh`, `tools/gh_app_token.py`), signing and the release pipeline (`tools/release/**`, `.github/workflows/ios-release*.yml`, `tools/devcap.py`, `tools/ci_hygiene.py`, `tools/release_closure.py`: the release job runs them with the App Store Connect key in reach), the review recorder and identity (`tools/review/**`, `tools/hooks/review_guard.py`, `.claude/agents/reviewer.md`) and git's own plumbing (`.git/**`, `.githooks/**`, `.gitmodules`, `.gitconfig`). The only way past the refusal is the owner at their own terminal with the owner acknowledgement (it asks for the head SHA). A test derives the release closure and the import closure of the kept set and fails when one of them is not protected; `record.py` imports no landing tool.
- **Review identity.** Only the reviewer (`agent_type` `reviewer`) records a verdict. `tools/hooks/review_guard.py` refuses a file tool writing `build/review/*.json` or `~/hass-agents/reviews/**`, refuses `record.py` from any other session, and leaves an identity stamp when the reviewer runs it; `record.py` copies it into the verdict as `reviewer` (`agent_type`, `session_id`), and `pr_land` and the interactive `lane_land` refuse a verdict without it. `record.py --lane BRANCH` also writes the file the interactive `lane_land` reads. The runner-launched lane review is separate: the runner parses the reviewer's own output and writes the record itself. A tripwire, not a wall: a script that writes the file is out of scope, and the independent review of the change that adds it is the cover.
- **Denylist layer 1.** `tools/ship.sh` runs `python3 tools/house_scan.py denylist --base-ref origin/<base>` before it pushes, and `pr_land` runs the same command on the exact PR head (fetched as `refs/pull/N/head`, checked out in a shared clone) with `--base-root` and `--config` set to the base branch's tree and `contracts/house_scan.json`: the head is judged by the **base's** `skip_prefixes` and allowlists, never its own, and `.plist`, `.svg` and `.xcprivacy` files are read too. Only hits the change adds against the base count, so debt still being scrubbed does not block every PR; without a base the command counts every hit in every file, debt paths included, and applies no skip list. The list is, in order, `HOUSE_SCAN_DENYLIST`, `~/.config/fenton-hass/house_denylist.txt`, then `~/hass-agents/house_denylist.txt` (the list the agents build; the owner approved it, 2026-11-07); house_scan reads it, agents never open it, and the output is counts, the source name (`env`, `config` or `agents`) and `path:line`, never a term. Any hit refuses. A list that is not loaded prints "denylist not loaded" and continues, unless `denylist_required` is true in the config, which then refuses (default false; the owner turns it on once the list exists).
- **Going public.** Build the snapshot with `python3 tools/public_snapshot.py SNAPSHOT_DIR [--ref origin/main]`, then publish it with `tools/go_public.sh SNAPSHOT_DIR SFenton/native-home`; the script is the only way. `public_snapshot.py` writes the blobs of the ref's tree (`ls-tree` plus `cat-file`, so no archive attributes, ignore rules or filters apply) into an empty directory (a non-empty one is refused), leaves out the short `PRIVATE_ONLY` list kept in the tool itself (never read from the tree; today `.gitleaksignore`, whose fingerprints name private commits), and makes one commit as `S+H <noreply@example.com>` ("Initial public snapshot"), with every git call in a scrubbed environment (no `GIT_*` variables, no system or global config, an empty template, hooks off, fixed dates). It then fails closed unless the committed tree equals the ref's tree minus the list (mode, blob id, path), the identity is exactly neutral, and there is no remote, tag, other ref or hook. Add to the list only files private by nature, never to hide a hit. It prints counts and the left-out paths. `merge_guard` refuses `gh repo create --public|--internal`, `gh repo edit --visibility` (anything but `private`), a visibility change through `gh api` (REST or GraphQL) and a `git push` to any remote that is not this repository's origin, and, for an agent session, runs the script only in that exact form from a checkout whose `go_public.sh`, `go_public_gate.py`, `house_scan.py` and config equal the base's. The script runs `tools/go_public_gate.py` first and only then creates the repository **private**, pushes the snapshot and makes it public. The gate refuses unless: the snapshot is one orphan commit on one branch with a clean tree (no history to hide a term in) whose author and committer are exactly `S+H <noreply@example.com>` with 0 remotes; house_scan has 0 hits judged by the **trusted base config** read from `origin/main` (the snapshot's own `skip_prefixes`, allowlists and debt are never read, and the base's are stripped); the denylist is loaded with at least 20 terms and has 0 hits in **every file type**; and gitleaks finds nothing in the files (`dir`) nor in the history (`git`). It prints counts and the denylist source only. Any gate failing keeps the repository private.
