Decision: The owner chose a logic-only coverage gate. Certification needs 95% logic line coverage from the Mac host `swift test`; UX source (`HassDesign`, `HassUI`, `FentonActivityViews`) is classified `unmeasured`. The UX tests, accessibility tests, app-hosted tests (`FentonHomeTests`) and journeys are kept and still ship with every UI change; the hosted suite is a pass or fail gate in `pr-checks` (the classes a diff reaches) and in the nightly `hosted` job (the whole suite on iPhone). Options judged: keep the 95% logic and 95% UX gates; speed up UX coverage (the instrumented-app plan: fewer parts, selected hosted classes, cached profiles); the logic-only gate plus hosted pass or fail (chosen). Keeping both gates was rejected because a per-change UX coverage run took 38 to 78 minutes and the nightly never completed the iOS phase. Speeding it up was rejected because it keeps the instrumented build, per-launch profiles and simulator reruns for a number nobody could act on without chasing lines in view code.
Replaces: the certification wording "95% logic and UX line coverage" in AGENTS.md and the testing docs.
