Decision: The phone keeps its last-known APNs and push-to-start tokens in the registration Keychain item, and every `mobile_app` sync carries them, so a sync never drops a token Home Assistant already holds. `LiveActivityCoordinator` hands the saved start token to `LiveActivityTokenReporter`. Nothing drawn, worded, animated or navigated changes. Options A, B and C were judged. A, wait for both tokens before the first sync (rejected: a background launch is suspended before they arrive, which is how the Duo lost its card); B, keep both tokens across launches and seed every sync with them, gated on notification permission and Live Activities being enabled (chosen); C, leave the app as it is and rely on the server alone (rejected: notifications still stop when the APNs token is late).
