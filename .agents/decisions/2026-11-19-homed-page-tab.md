# Homed pages: a page opens under its home tab, from any tab

Decision: a page that `extensions.routes[].tabId` places under a tab is homed there (no route, or routes naming different tabs: not homed). A `push` from a page, or the push that follows a sheet's dismissal, to a homed page whose home tab is shown and is not the selected tab selects the home tab and puts the page on top of that tab's stack; a page already in that stack is popped to, and one already on top only shows. A page with no home tab, a page whose home tab is the selected one, and a page whose home tab is hidden open on the tab showing, as before; a push to a level of the sheet stays in the sheet. The owner asked for it (2026-11-19): "On Settings tab, open Quick Links -> Rooms -> pick a room. Navigates to room but remains under Settings tab. In the previous, non-config-based native app, we had a bunch of pages that were nested under each tab. Rooms were one of those." The request names the result (the old app), so no options were built; the choices inside it were judged from `build/research/room-tab.md` and the HIG. Stack, options A and B: A on top of the home tab's stack as it stands (picked: the old app's `pushOnHome`, and HIG Tab bars, a tab bar "preserves navigation state within each section", which this app's motion rule repeats for every tab switch); B trim the home tab to its root first, as a system route does (lost: it discards the pages the owner left open on Home for a link that never asked to, and Back would always lead to the root instead of where Home was). Motion, options A and B: A the sheet closes with the system dismissal, then the tab changes as a cut with the page already on top, no push drawn (picked: the old app, and the tab rule that content never slides or fades on a tab switch; HIG Motion, "Add motion purposefully; gratuitous or excessive animation distracts"); B cut to the home tab, then an animated push (lost: a third motion in a row, and it flashes whatever Home last showed before covering it). Back from the landed page pops within the home tab's stack, to the page that was on top of it (the tab's root when it held none); it never returns to the tab the link was tapped on. That tab keeps its stack: on return it shows the page the sheet opened over, with the sheet closed. The sheet still closes first and a form with unsaved changes on the tab being left asks first. iPhone, folded and unfolded Duo and iPad follow one rule: only where the system draws the tab bar differs (iPad at the top), an adaptive column on the tab being left is removed before the tab changes, and the landed page opens by the columns' rule of the home tab. Not judged on a device: the Verifier's evidence for the three families is still to come.
