# Mockups

> **What:** the atlas of every page, modal, component and flow in S+H as the app draws it today, on iPhone, iPhone Duo and iPad, in every state, with its motion playable; plus the owner-review proposals. **Read when:** before you change or add anything visible (look the surface up here first), when you need to know how a screen looks or moves, or when you propose a change ([propose-first](../../workflow/propose-first.md)).

**In the Claude app:** the whole atlas, proposals and kit gallery are one private hub Artifact: https://claude.ai/artifact/D566bWMJYibs3HJZSD6Jba. It is built from this folder by `tools/mockups_hub.py` and published to that one link ([skills/mockup-hub](../../skills/mockup-hub/SKILL.md)); never edit it by hand and never publish a mockup as its own Artifact. A repo-only mockup cannot be opened in the app, so a mockup is not done until it is in the hub.

## Find the mockup

1. Look the surface up by id or title in the folder indexes below, or search `catalog.json` (`jq '.items[]|select(.sources[]|contains("Features/Chores"))|.mockup' catalog.json`). The catalog links each item to its source files, spec docs, patterns, the sheets it opens and the page that presents it.
2. Open the HTML in a browser: `python3 -m http.server 8077 --directory .agents/design/mockups`, then `http://localhost:8077/<path>`. It works from `file://` too. Controls: device, state, appearance, text size (Large to AX5), Reduce Motion and Transparency, Play.
3. Each folder has a `README.md` (status, sources, spec, states, motion, open notes) so you can tell what is covered without opening the page.

## The rules for agents

- **Map before you change.** Find the surface here, read its README, open it. Then follow [propose-first](../../workflow/propose-first.md).
- **Update with the change.** A change that alters what a surface draws, a state it has, or how it moves updates that mockup in the same PR (its states, motion, a11y, source map, change log, status), and `tools/mockups_check.py` and `tools/mockups_index.py --check` pass. A new surface gets a mockup, a folder README and a catalog entry.
- **Windows and the hinge.** List all six windows (iPhone, Duo folded, Duo unfolded portrait and landscape, iPad portrait and landscape) unless the surface is device-specific (a Live Activity, the Watch); macOS is not a target. Duo splits follow the hinge posture rule ([split-view](../apple/split-view.md)); landscape surfaces get the kit-made Reflow and hinge section.
- **Reuse the kit.** Check `_kit/components` and [patterns](../../patterns/README.md) before you draw a new view; one component, one implementation. Helpers named `_<batch>.js` beside a mockup are local, marked "promote to kit".
- **Always republish.** Any change under this folder ends with `python3 tools/mockups_hub.py`, a publish to the hub link above with the Artifact tool, and `python3 tools/mockups_hub.py --mark-published`, without being asked ([skills/mockup-hub](../../skills/mockup-hub/SKILL.md)). Give the owner the hub link, never HTML or a file path. The Stop hook `tools/hooks/mockup_hub_guard.py` blocks ending a session that changed mockups until the hub is rebuilt and marked published; a session with no Artifact tool says the republish is pending in its PR.
- **Lifecycle.** An agent sees only current designs; history exists to explain why. `shipped` is on `main`. `proposed` is awaiting the owner. `decided` is picked (needs `decision`: the rule doc that records the outcome, or `PR #n`; a proposal page that records its own decision may link to itself; and `shippedIn` once built); it leaves the current list and sits in the hub's "Why" section. `superseded` was replaced (needs `supersededBy`, a catalogued id). `designed-not-wired` exists in code with no call site. `placeholder` is a stub. `inFlight` (a branch name and a note) is only for work decided but not yet on `main`; when the branch merges or is deleted, clear it and set the status to `shipped` in the merging PR. Never keep a "was" state for something that has shipped: git history has it. `tools/mockups_check.py` fails on an `inFlight.branch` that is the PR's own head branch (it must be cleared in the merging PR), or that is merged into the PR's base (`GITHUB_BASE_REF`, else `main`) or deleted, a `source:` path that does not exist, an `.html` the catalog does not list, and a decided proposal with no decision link.
- **The mockup is a map, not a spec.** Where it and the code disagree, the code wins and the mockup is fixed. Decisions and rules live in the docs beside this folder.
- **Reviews.** Each mockup carries a dated `apple-hig` and `swiftui-pro` review: `fix` findings describe where the app falls short today (they are findings, not changes made), `departure` cites the owner decision.
- **Share as one file.** `python3 tools/mockups_inline.py <mockup.html> > out.html`.
