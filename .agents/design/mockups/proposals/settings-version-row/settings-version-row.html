Settings version row

Show which build is running, so a bug report or a support question names the exact version. The text comes from AppBuildInfo (built with the version stamping in .agents/workflow/versioning.md); this proposal is only about where and how it appears.

Cause and goal

Release builds will carry YYMM.DD.NN versions, a build number and the commit. Nothing in the app shows them yet. FestivalNativeApps puts App Version in Settings with the version, build and short commit (2610.02.17 (57) · 42edc57), and VoiceOver reads each part by name. Local and simulator builds read 0.1.0 (1) with no commit.

Shown below: today (no version anywhere on Settings) is the bottom of the list, Performance then Report an Issue. Each option adds one thing under it. iPhone at the default text size, then at AX5 for the recommended option. iPhone Duo and iPad draw the same list (pages/settings in the atlas); the row has no width-dependent layout, so no split-view change.

Standard Settings idiom (HIG, Lists and tables: a value row). Tapping copies the full text to paste into a report; the row announces “Copied” and the copy uses a success haptic. Title stays “Version” (not “App Version”: the app is the screen's subject).

Recommendation

B. It is where people look for it, it can be copied into a report with one tap, and it reads cleanly in VoiceOver by naming each part (AppBuildInfo.spokenVersionText). Files: SettingsScreen.swift (one section after Report an issue), a small VersionRow, tests in HassUITests and a UI journey on all three device families; update the Settings page atlas mockup in the same PR.
