Proposal · 2026-11-02 · DRY-9998 (dry run, nothing built) · L2 design

Smooth page motion on single-page layouts

Bring the unfolded Duo's column motion (pages move over one still wallpaper) to iPhone, folded Duo and Duo/iPad portrait, and answer how one shared wallpaper behaves when you switch tabs.

1. Goal and cause

The owner (2026-11-02): smooth page and sub-page transitions on the unfolded Duo in Settings; in folded, portrait and iPhone layouts "I still see pages transition in individually, swapping the background". Second question: "How would shared background work with tab navigation?"

Cause (read from code, not captured; research build/research/dry-9998-settings-motion.md R1). In the split layout the pages are transparent hosts moved by frame over one static wallpaper (UKColumnsViewController.swift:434-496, smooth spring 0.3 s). On a single page the stock UINavigationController push runs and every pushed page draws its own opaque UKBackdropView (UKPageViewController.swift:94-100), so a push slides one full wallpaper over another, with the system's 30% parallax, dim and edge shadow on the wallpaper itself. The shell already draws one window-level wallpaper behind the tab controller (UKShellViewController.swift:84-89); pages just do not rely on it.

Rules on record. design/motion.md §2 and §4.2: push and pop are the system's, "Never replaced, slowed or decorated". §4.1: a tab switch is a cut, "No custom tab transitions, ever". The columns are the only approved departure (split-view, owner 2026-11-01). Every option below except "Today" departs from §2/§4.2 to some degree; none touches §4.1.

4. Tab switches with one shared wallpaper

What stays

The wallpaper is one view per window, behind the tab bar controller (it exists today). It never moves, re-renders or cross-fades on a tab switch, a push, a pop or a rotation. The tab bar (or the Duo rail), Quick Links and Profile also stay.

What changes

Only the page on top, as a cut (§4.1 unchanged, "no custom tab transitions, ever"). Each tab keeps its own stack and scroll position: leave Settings two levels deep, visit Home, come back, and you are two levels deep with the same wallpaper behind you. Nothing cross-fades.

Re-tapping the tab

The first re-tap pops to the root with the same motion as Back in the chosen option (B: the top page slides out to the trailing edge, the root slides in from the leading edge; intermediate pages are skipped). A second re-tap scrolls to the top. On iPad portrait the tabs live in the flyout; its slide is unchanged and the page behind it cuts.

Why not per tab

One wallpaper per tab or per section would render the photo several times, bring back the swap on a tab switch, and needs a rule nobody asked for (page-backdrop R2: "pushes, tabs and splits all show one picture").

5. Recommendation: B

B, for every section's pushes, not only Settings. It is the motion the owner already likes, made literal: the same token (UKMotion.standard, smooth spring 0.3 s), the same direction and the same still wallpaper as the columns, so unfolding or rotating a Duo or iPad changes the layout but not the motion language. It removes the per-page wallpaper and its per-frame display-link tracking, so the main thread does less during a push.

  • HIG, Motion: "Add motion purposefully" and "make feedback realistic and consistent with gestures and expectations"; "As much as possible, let people cancel animations rather than wait for completion". B's motion shows where you are in the hierarchy (deeper is to the right, in both layouts), and the swipe back is cancellable mid-way.
  • HIG, Motion: "System components provide familiar motion". This is the case for the rule we are departing from: the system push is familiar. B keeps the familiar parts (direction, edge swipe, Back button, timing close to the system's) and changes the parallax, dim and shadow.
  • HIG, Gestures: "Supplement standard gestures, don't replace them": the leading-edge swipe and the Back button both stay; on iOS 26 the content swipe must drive the same animator.
  • HIG, Tab bars: a tab bar "preserves navigation state within each section"; keep the bar visible between sections. Unchanged: tabs cut, each stack is kept.
  • HIG, Accessibility, Reduce Motion: "replacing axis transitions with fades" and "tracking gestures directly". B cross-fades at 0.2 s and keeps the finger-tracking swipe.

Gate before rollout: a one-section spike (Settings) with frame captures (UK_RECORD=1) and tools/ios_navperf.sh; if the bar, flyout edge pan or iOS 26 swipe do not come out clean, fall back to A2 (smaller departure, same wallpaper).

6. Open questions for the owner

  1. B, A2 or Today? (Recommended B.)
  2. Every section, or Settings first? (Recommended every section, after the Settings spike.)
  3. On iOS 26, should the swipe anywhere on the page also go back? It competes with sideways-scrolling chip rails. (Recommended: edge only for now, same as iOS 17/18.)

Notes

  • Fidelity: the Back button and the bar title move with their page here; the system bar cross-fades them in place. That is the same in every option, so the comparison holds. Quick Links, Profile, the tab bar and the Duo rail are drawn once on a fixed layer, as UIKit draws them.
  • Timing: Today and A use the kit's system push (Mock.anim.easing.push, 0.35 s); B uses UKMotion.standard drawn as a critically damped spring that reaches rest in about 0.45 s; Reduce Motion uses Mock.anim.ms.quick() (0.2 s) for B and the system's 0.35 s cross-fade for the others.
  • The Admin Controls and Automation Overrides bodies are stand-ins built from the Settings kit helpers (SA.section, SA.link, SA.toggleRow); the subject is the motion, not the copy.
  • Finding, columns under Reduce Motion: pages that stay on screen still move between columns for 0.2 s (UKColumnsViewController.swift:486-490, reduced: .quick drives the frame change), and the interactive back is switched off (:554). B cross-fades in place and keeps the swipe; aligning the columns is an L1 follow-up. The split reference here draws the columns as the code does.
  • Promote to kit in a real run: Mock.anim.slide (both pages a full width, standard spring) beside Mock.anim.push, and a shared-wallpaper layer option for Mock.page.
